After the protected production approval gate, the helper verifies the repository, event, main ref, source/run SHA, exact action and reviewed origin. It reads authoritative `refs/heads/main` from the fixed GitHub API endpoint and only then emits `approved_commit`. Missing, malformed or unavailable lookup results fail closed without raw response/token logging. Reused workflow attempts are rejected; a rerun needs a new dispatch and approval.

Every downstream side-effect job consumes that immutable approval output. The production verifier checks current main immediately before every POST, including after each retry delay; both status publishers recheck and target only the approved SHA. The existing 72-attempt cap, 10-second delay, request timeouts, 15-minute probe-job deadline and controlled-response assertions remain. Lookup failures do not automatically retry or permit production requests. If main advances after a pending status, no stale success is published; the pending status may remain while the failed Actions run records rejection.

These checks are not an atomic GitHub-main/production transaction or cross-workflow merge lock. Any separately authorized future probe requires a coordinated no-merge observation window and verification of actual environment reviewer/self-review/bypass settings. A YAML environment name alone is not proof of those protections. Canonical-origin work remains #735's prerequisite.
