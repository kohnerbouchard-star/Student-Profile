# REF-046 — Make Campaign scheduling a thin application trigger

Status: PLANNED. Risk: R3. Dependencies: REF-032, REF-033. Maps to ARCH-209/ARCH-600.

## Read first

`backend/supabase/functions/campaign-orchestrator/index.ts`, `backend/src/domains/campaign/services/campaignCoordinator.ts`, `campaignStateMachine.ts`, World runtime and Arrival scoring contracts/tests, current lease/due-work implementation and scheduler inventory.

## Allowed change

One Campaign trigger-to-application boundary and its exact dependency injection/tests. No new scheduler, cadence, game-time model, Story event, Arrival scoring, economic effect, cron setting or SQL. Budget: ten meaningful files.

## Implementation

1. Identify trigger-only responsibilities (auth, bounded due-work discovery, job/lease identity) versus Campaign state transitions/effect preparation already owned by services.
2. Delegate any remaining duplicated transition logic to the existing coordinator with explicit game/clock/lease inputs. Do not introduce a second Campaign engine or move rules into a generic scheduler helper.
3. Preserve trigger batch limits, pause/resume behavior, tick/event identity, retry semantics and atomic persistence. Keep all state game-scoped.
4. Retain existing Arrival/Countries/Story interfaces and absence/decline behavior. Do not invent new narrative or geopolitical events during cleanup.
5. Test duplicate trigger, competing worker, no due work, paused game, missing runtime state, lease expiry, effect failure and two games at different campaign stages.

## Acceptance and validation

The entrypoint only triggers the same coordinator; one logical event advances at most once with unchanged effects. No new cross-domain mutation or schedule exists. Run backend `test:world-runtime`, current Campaign/Arrival tests and Admin campaign-worker tests, auth/lease checks, full typecheck/smoke and architecture audits.

## Stop / rollback

If already thin, record verification-only evidence instead of adding wrappers. Stop if transition/lease semantics or SQL must change. Revert source wiring only; do not rewind campaigns, replay live events or alter production cron.
