# REF-005 — Extend existing architecture ratchets for the selected seams

Status: PLANNED. Risk: R1. Dependencies: REF-003, REF-004. Maps to ARCH-001 extension; its original completion remains intact.

## Read first

`scripts/architecture/architecture-ratchet-v2.mjs`, the inventory generator, `scripts/high-priority-boundary-ratchet.mjs`, `scripts/legacy-runtime/legacy-browser-transport-ratchet.mjs`, root audit scripts and REF-003 dispositions.

## Allowed change

Existing architecture tooling and its focused fixtures, plus one reviewed scoped baseline derived from current source. No application changes, new test framework, broad workflow rewrite or raised debt ceilings. Budget: eight meaningful files.

## Implementation

1. Reuse the current scanner/ratchet conventions; identify which desired rules already exist and add only missing assertions.
2. Freeze the exact allowed Classroom forwarding/import families and selected browser interception sites. Reject new unregistered sites while permitting measured existing debt to decrease.
3. Add a deletion-proof check for records selected by this program: canonical replacement, caller evidence, disposition and ownership must exist before the path is removed. Do not let an arbitrary `approved=true` replace evidence.
4. Preserve zero-tolerance checks for browser database access, direct money/inventory authority bypass and unscoped state. Keep production/test/fixture classifications distinct so useful fallback code is not banned.
5. Add negative fixtures for a new proxy caller, new fetch monkey patch, direct economic mutation and missing removal record; add positive fixtures for an existing permitted seam and ordinary image/error defaults.

## Acceptance and validation

A clean exact-main scan passes without relaxing pre-existing ceilings. Every injected forbidden pattern fails the relevant check. Repeated generation is deterministic. Run `npm run audit:architecture`, `npm run audit:high-priority-boundaries`, `npm run audit:legacy-runtime`, focused tool tests and secret/diff checks. Document exclusions precisely; do not exclude an entire domain to silence a match.

## Stop / rollback

If a rule cannot distinguish legitimate data/read behavior, narrow the detector and retain a review candidate instead of blocking or deleting working code. Revert only this incremental tooling change; do not remove inherited guards.
