2. Move the submission-only lookup behind a Contracts read repository with both game and submission predicates. Retain the established `contract_submission_not_found` response and reject cross-game/contract mismatches before the mutation.
3. Normalize each alias into one internal command carrying approved Staff/game context, contract/progress identity, original body and current request/idempotency identity. Do not silently change payload hashing.
4. Invoke the existing review authority once. Carry all validations/audit/replay checks from the downstream path into the local use case; do not implement another status transition table.
5. Return the original alias envelope/status and keep unrelated `handleGameWrite` branches unchanged. Record zero Classroom fetches for these three aliases only.

Test wrong game/contract, unsupported method, missing progress, repeated review, conflicting replay, repository failure and immutable audit behavior. Assert one review transaction and no extra reward issuance. Run backend `test:admin-api`, `test:admin-local-mutations`, Contract acceptance/lifecycle, economic-ledger invariants and focused disposable-database replay/race acceptance.
