# REF-024 — Converge Marketplace reservation access on Inventory public ports

Status: PLANNED. Risk: R3. Dependencies: REF-023. Maps to ARCH-204/ARCH-300.

## Read first

`backend/src/domains/marketplace/infrastructure/marketplaceInventoryReservationAdapter.ts`, Marketplace listing/purchase repository and funding response contracts, REF-023 Inventory boundary, current reservation/settlement SQL and negative-state tests.

## Allowed change

This reservation adapter and its exact Marketplace contract/import consumers plus tests. Preserve existing Marketplace-owned settlement orchestration. No fee/pricing/currency, listing lifecycle, database projection function, SQL migration or UI changes. Budget: ten meaningful files.

## Implementation

1. Record the current reservation identifiers, owner/game binding, quantity representation, receipt/fingerprint mapping and transaction location for create/activate/purchase/cancel.
2. Replace imports of Inventory internals with the approved public semantic contract. Extract only transport/database-name translation that belongs inside Marketplace infrastructure.
3. Preserve the existing single settlement transaction for money, inventory transfer, reservation release and fees. Do not call Banking and Inventory independently to emulate that transaction.
4. Keep intentionally retained legacy SQL projections classified as required until live function/dependency evidence permits a separate forward migration. A filename containing `legacy` is not removal authority.
5. Characterize stale reservations, seller/buyer same or different game, insufficient quantity/funds, duplicate cancel, replay conflict and two competing purchases.

## Acceptance and validation

No selected cross-domain infrastructure import remains; one authoritative settlement path remains; returned funding/reservation receipts are byte/semantically equivalent where expected. Failed/concurrent requests cannot leak or oversell stock. Run backend `test:player-marketplace`, `test:player-inventory`, `test:economic-ledger-invariants`, Player `marketplace-connected`, owning disposable-database acceptance and shared checks.

## Stop / rollback

Stop if cleaning the adapter requires changing historical SQL projections or settlement formulas. Revert the TypeScript boundary only; no compensation by manually releasing real reservations or rewriting trade records.
