# REF-004 — Capture bounded behavior-parity fixtures

Status: PLANNED. Risk: R1. Dependencies: REF-002. Maps to ARCH-300/ARCH-400.

## Read first

Existing `backend/supabase/functions/admin-api/common.test.ts`, `compatibilityOperations.test.ts`, current game-route tests, `backend/src/domains/contracts/api/staffContractHttpHandler.ts` and its tests, Player access-code-reset tests, and package registrations. Use the actual handlers selected by REF-002.

## Allowed change

Tests/fixtures for the five residual adapter families only, plus minimal registration in their existing owning test script. Proposed evidence: `REF-004/parity-matrix.json`. No production implementation edits. Budget: ten meaningful files; split fixtures by route family if that ceiling is exceeded.

## Implementation

1. Capture synthetic request/response fixtures for Contract progress, review aliases, reward issue and Player access-code reset. Include methods, status/error codes, headers, aliases, required context and public-key translation.
2. Spy on repository/RPC invocations and security checks, not only serialized success bodies. Record zero calls for denied requests and exactly the existing authoritative command for valid mutations.
3. Cover wrong owner/game/player, unsupported method, expired/revoked auth, unavailable dependency, idempotent replay and conflicting payload. Include review transitions and duplicate reward attempts.
4. Normalize only intentionally nondeterministic fields through injected clocks/IDs. Do not scrub error codes, order, monetary values, currency, effect counts or identity fields merely to make fixtures match.
5. Keep fixtures synthetic and domain-owned. Register the cases in the current suite; avoid a new repository-wide harness or snapshotting production records.

## Acceptance and validation

Fixtures fail when scope checks are removed, a second reward is posted, an alias resolves to another game or an unexpected response field appears. Existing behavior is documented, including known bugs as separate issues rather than silently corrected expectations. Run `npm --prefix backend run test:admin-api`, `test:admin-local-mutations`, `test:player-contract-acceptance` and relevant auth checks from VALIDATION.md.

## Stop / rollback

An unstable or already-failing baseline blocks the affected adapter ticket. Do not rewrite existing assertions to match a planned refactor. Revert additive fixtures/registration only if their assumptions are disproven.
