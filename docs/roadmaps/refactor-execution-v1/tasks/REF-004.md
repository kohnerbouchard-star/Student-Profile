### Recorded issues, not fixes

`REF004-OBS-01`: Admin progress forwarding drops the original filter query even though the direct Staff handler supports filters. Any correction needs separate behavior-change acceptance; these fixtures intentionally expose the difference.

`REF004-OBS-02`: the legacy approval alias reviews before attempting reward issuance. A reward rejection can follow a successful review; this is not one atomic transaction. Review-only aliases must not gain that automatic reward side effect.

`REF004-OBS-03`: the Staff review handler does not enforce the provided retry header as a same-payload receipt. Repeated/changed review actions can execute again. The fixture records the existing behavior rather than asserting an invented conflict response.

`REF004-OBS-04`: credential replacement sends neither request-id nor idempotency-key as an RPC argument. Identifier-only updates neither replace credentials nor revoke sessions. These are separate behavior contracts, not permission to add deduplication or revocation during a refactor.

The receipt stubs prove adapter calls and response handling, not SQL locking, conservation or concurrency. No old Staff reward-then-mark implementation is substituted for the current Admin atomic authority. The identifier-only handler has no injected clock: its actual timestamp is checked against the execution interval, not scrubbed.
