# REF-006 — Move the retained Messaging dispatcher to its domain owner

Status: PLANNED. Risk: R2. Dependencies: REF-005. Maps to ARCH-400/ARCH-402. Recheck #668/#736 before touching Player composition roots.

## Read first

`backend/supabase/functions/player-api/runtime.ts`, Classroom index and the exact Messaging dispatcher import resolved by REF-002; `backend/src/domains/messaging/api/`; the existing Player Messaging/rate-limit tests. Search current source for `classroom-api` and Messaging dispatch references rather than assuming the historical import remains.

## Allowed change

One dispatcher implementation, its two composition-root imports, a temporary re-export only if required, and focused tests. Proposed destination if no suitable current owner exists: `backend/src/domains/messaging/api/playerMessagingDispatch.ts`. No auth/client factory, route table expansion, UI or database edits. Budget: eight meaningful files.

## Implementation

1. If canonical Player code already imports a neutral/domain-owned dispatcher, record verification-only disposition and remaining references; do not move it again.
2. Otherwise move the existing dispatcher byte-for-byte first, adjusting only imports. Domain-specific route parsing belongs under Messaging; unrelated composition remains in the Player root.
3. Wire Player directly to the new owner. Classroom may import the same implementation or temporarily re-export it one-way; the new owner must never import Classroom.
4. Preserve supported methods, rate-limit keys, context forwarding, participant/game checks, idempotency and safe response mapping. Do not re-create session/service-role dependencies during dispatch.
5. Characterize both roots and check the runtime import closure/cycles. Remove only genuinely unused imports; retain still-required compatibility exports until REF-048.

## Acceptance and validation

Player-to-Classroom implementation imports for this dispatcher reach zero; exactly one implementation remains. Same requests produce the same status/body and service-call counts through both roots. Run backend `test:player-messaging`, `test:player-security`, `test:player-request-scope`, `typecheck:all`, Player `messaging-connected`, and shared architecture/auth checks.

## Stop / rollback

Stop if the owner PR is active or movement would redesign cross-domain routing. Roll back by reverting this source move/import wiring without changing route behavior or resurrecting an independently retired runtime.
