# REF-047 — Archive one verified historical source family and reconcile empty namespaces

Status: PLANNED. Risk: R1. Dependencies: REF-003, REF-015. Maps to ARCH-700.

## Read first

`backend/legacy/README_CODEX_HANDOFF.md`, the specifically classified Apps Script/router reference files, build/deployment/source-test roots and REF-003 register. Inspect `analyst`, `audit` and `games` namespaces and their callers; `games/tests/gameLifecycleMigrationContract.test.ts` is registered test coverage, not disposable merely because the namespace is small.

## Allowed change

At most one historical source family (up to three files) plus its archive index/links and namespace disposition documentation. Proposed archive: `docs/archive/legacy-apps-script/`. No workbook edits, historical migration moves, wholesale `backend/legacy` deletion, feature removal or active-test deletion. Budget: eight meaningful files.

## Implementation

1. Prove the selected files are historical reference rather than runtime/build/test authorities. Search indirect action-name/fixture readers and deployment packaging, not just imports.
2. If the existing location is already clearly archived and excluded, document that state; do not move files merely to improve a metric.
3. Otherwise move only the verified family, preserving content/history and a tombstone at the former reference index with replacement paths and reason. Scan before copying; never reproduce secrets found in historical material.
4. Keep migration rationale and useful domain requirements discoverable. Update only exact broken documentation/tool references; preserve behavioral fixtures and checks.
5. Classify empty/small namespaces separately in the register: placeholder, retained test owner, feature scope or obsolete. Any physical namespace/test migration becomes an explicit child/next ticket, not a second source cleanup hidden here.

## Acceptance and validation

No runtime/build/test consumer loses a required file; archived records remain discoverable; code removal is distinguished from simple relocation. Run file/link/asset and secret scans, affected tooling tests, backend `test:game-lifecycle` when references are touched, architecture checks and diff validation.

## Stop / rollback

Unknown consumers, active migration authority or embedded secrets block copying/deletion. Revert the move/reference update only. Do not delete useful history or weaken scans to make the archive pass.
