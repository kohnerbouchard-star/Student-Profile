# REF-026 — Remove Store-handler persistence without replacing purchase settlement

Status: PLANNED. Risk: R3. Dependencies: REF-023, REF-024. Maps to ARCH-202/ARCH-300.

## Read first

`backend/src/domains/store/api/playerStorePurchaseHttpHandler.ts`, `playerStorePublicHttpHandler.ts`, `store/index.ts`, public/funding repositories and current purchase/offer tests. First determine which handler is canonical, retained compatibility or unreachable; do not improve an unused old purchase path.

## Allowed change

One reachable purchase adapter's remaining direct persistence and its existing Store application/repository seam. No catalog redesign, offer type, stock/funding/FX SQL, price/reward change or new purchase API. Budget: twelve meaningful files.

## Implementation

1. Trace system offers versus Business offers, public-key translation, quote/funding selection, purchase command and returned receipt. Preserve their intentionally different authorities.
2. If the flagged handler is no longer reachable, record evidence for later retirement and do not create a new service. Otherwise extract its database details into the current Store repository/command adapter.
3. Reuse the existing atomic purchase transaction and owner-approved Inventory/Economy boundaries. Do not introduce separate debit, grant and seller-credit calls or reimplement Business offer settlement.
4. Preserve paused-game denial, explicit currency, quote expiry/fingerprint, account selection, stock capacity, idempotency and safe public response fields.
5. Test system/business purchases, stale quote, unavailable funding, insufficient stock/funds, duplicate/replayed order and concurrent final-unit purchases.

## Acceptance and validation

The selected handler's raw persistence disappears while all purchase authorities, effect counts, receipts and errors remain stable. No duplicate economic/inventory path is created. Run backend `test:player-store-public`, `test:player-inventory`, `test:economic-ledger-invariants`, Player `store-flow`, `store-connected`, `store-negative`, Business workspace checks and affected database/race acceptance.

## Stop / rollback

Stop if the legacy handler's remaining consumers are unknown or a schema/settlement change is needed. Revert only the bounded source extraction. Never roll back purchases by editing balances or inventory directly.
