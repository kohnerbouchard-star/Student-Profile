# REF-043 — Converge Admin V2 Banking response and error adaptation

Status: IN_PROGRESS. Risk: R2. Dependencies: REF-005. Maps to ARCH-500/ARCH-501.

## Read first

`admin/v2/src/routes/banking/BankingApi.js`, `BankingController.js`, `BankingRoute.js`, `admin/v2/src/api/admin-api-client.js`, `admin-bff-transport.js`, current Banking unit/browser tests and public DTO contract.

## Allowed change

One Banking response/error normalization seam and its exact controller callers/tests. Reuse the existing shared API client; proposed `routes/banking/BankingResponse.js` only if domain-specific projection is duplicated. No other route migration, BFF auth, backend, layout, account model or financial behavior change. Budget: eight meaningful files.

## Implementation

1. Inventory duplicate success/envelope/error handling for one Banking operation family, keeping validation, authorization, conflict and unavailable-service errors distinct.
2. Move only the repeated domain projection to an explicit adapter or use the existing shared client helper. Preserve safe fallback labels; ordinary defensive defaults are not legacy deletion targets.
3. Keep Checking/Savings, currency identity, numeric representation, pagination, selected-game binding and public identifier redaction unchanged.
4. Preserve stale-response cancellation, pending/disabled states and authoritative post-write refresh. Do not retry a Banking mutation automatically after an ambiguous failure.
5. Test empty accounts, malformed safe response, permission denial, failed adjustment, conflicting replay, route/game switch and duplicate click.

## Acceptance and validation

One normalization owner and unchanged public Banking behavior; raw UUIDs, privileged errors and credentials remain absent from rendered state. Run `npm run test:admin-v2`, `npm run test:admin-v2:browser`, `npm --prefix backend run test:player-banking-public`, `npm run test:admin-economic-writes`, affected Banking/browser cases and the shared checks.

## Stop / rollback

Stop if response normalization would conceal an actual API-contract bug or require backend changes. Revert the adapter and caller edits; do not reintroduce global fetch interception or change balances.
