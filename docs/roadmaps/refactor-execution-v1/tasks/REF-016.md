# REF-016 — Adopt the existing Players public boundary in one consumer family

Status: PLANNED. Risk: R2. Dependencies: REF-006. Maps to ARCH-100/ARCH-402. Reconcile #668/#736 before activation.

## Read first

`backend/src/domains/players/index.ts`, `players/api/playerRequestScope.ts`, `playerSessionHttpHelpers.ts`, current context-owner map and Messaging API consumers. The public index already exports the context factory/scope checks/route segmentation/session helpers; do not create another facade.

## Allowed change

Messaging's existing deep imports of those already-exported Players symbols and focused composition/context tests. An additional explicit export is allowed only when the same existing public capability is necessary and the owner approves it. No context reconstruction, new shared auth package, broad barrel or other domain sweep. Budget: eight meaningful files.

## Implementation

1. Inventory each Messaging import from Players internals, distinguishing value imports from type-only imports. Record the exact resolved symbol and current runtime closure.
2. Replace import specifiers with named imports from `players/index.ts` only where the symbol is already approved there. Preserve aliases/types and do not change call order or parameters.
3. Preserve the exact frozen server-created context object through the dispatcher and handler. Do not substitute `{...context}` or re-resolve identity from request payloads.
4. Verify no new runtime cycle or unintended module initialization appears through the index. Keep type-only dependencies erased and avoid exporting repositories/service-role client factories.
5. Update the existing cross-domain import inventory for these consumers only and record remaining domains for later tickets rather than editing them now.

## Acceptance and validation

Selected Messaging deep imports fall to zero without increased runtime authority, changed public HTTP contracts or context identity loss. Run backend `test:player-request-scope`, `test:player-security`, `test:player-messaging`, `typecheck:all`, Player `messaging-connected` and architecture checks.

## Stop / rollback

If the active context owner changes the same symbols, wait/reconcile rather than cherry-picking. If an internal helper is not an approved public capability, record it instead of exporting everything. Revert only these import/export edits; preserve merged auth fixes.
