# REF-013 — Converge the legacy Player access-code UI bridge

Status: VERIFIED_COMPLETE. Risk: R2. Dependencies: REF-010. Maps to ARCH-500/ARCH-700.

## Read first

`admin/player-access-code-bridge.js`, the exact Player drawer/reset action source discovered through REF-002, `admin/auth-session-manager.js`, canonical Admin API client and reset browser tests. Player creation and generic drawer wiring are adjacent protected behavior, not additional objectives.

## Allowed change

The reset action's browser adapter, its source-owned event registration and tests. Proposed explicit helper: `admin/player-access-code-reset-controller.js` only if no current owner exists. No credential generation in the browser, login/MFA changes, unrelated create-player refactor or generated bundle edits. Budget: eight meaningful files.

## Implementation

1. Verify the legacy bridge has a live consumer; otherwise supply evidence to REF-015 and make no replacement code.
2. Route the existing reset control directly through the canonical Admin BFF/client and the REF-010 endpoint, preserving confirmation, public identifier mapping and request identity.
3. Replace only the bridge's generic interception/event workaround with a scoped reset handler that is installed once and explicitly disposed.
4. Preserve busy/disabled/error states, focus restoration, one-time display behavior and approved secret exposure. Never log returned codes or store them in persistent browser storage as part of cleanup.
5. Test closing/reopening the drawer, switching the selected game and receiving a stale reset response. A response for an old game must not update the new game's UI.

## Acceptance and validation

One click/confirmed action produces one request; cancellation produces none; replay/retry preserves the server key contract. Wrong-game/permission failures remain safe and visible. No new global fetch patch exists. Run reset/browser cases, `npm run test:admin-v2`, `test:auth-boundaries`, `test:web-session-release`, asset/interaction and architecture checks.

## Stop / rollback

Stop if the reset flow depends on an unreviewed auth incident or generated-only source. Revert the UI adapter and listener wiring, not credentials or user sessions. Other Player drawer/create bridges remain separately classified rather than deleted in this task.
