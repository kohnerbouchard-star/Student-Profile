# REF-033 — Extract pure Story-effect preparation from persistence

Status: PLANNED. Risk: R3. Dependencies: REF-030, REF-032. Maps to ARCH-209/ARCH-300.

## Read first

`backend/src/domains/storylines/contracts/storyEffectContracts.ts`, `services/storyDecisionRoleplayService.ts`, current effect preparation/execution services and tests, and the actual transactional persistence boundary. Identify a genuinely pure calculation before moving it.

## Allowed change

One effect-preparation function family with its types/tests, plus the existing executor call site. Proposed target: `storylines/services/prepareStoryEffects.ts` if no suitable owner exists. No new effect kinds, narrative/reward/policy tuning, external AI behavior, outbox infrastructure or SQL changes. Budget: ten meaningful files.

## Implementation

1. Record inputs, effect ordering, dependency on context/time/randomness and resulting effect descriptors. Distinguish pure preparation from external model calls and persistence.
2. Extract preparation to accept explicit immutable inputs, supplied clock/random values where already used, and existing effect types. Do not manufacture deterministic results for external inference.
3. Keep the executor and its single existing transactional ordering unchanged. The pure function returns a plan/descriptor; it does not enqueue notifications, pay rewards or mutate Contracts itself.
4. Preserve numeric/rounding behavior, eligibility, relationship effects, fallback/decline/absence outcomes and replay identity. No player-facing prose rewrite is part of this move.
5. Compare baseline/extracted descriptors and final receipts for accepted, declined, unavailable and repeated decisions, including failure between validation and transaction commit.

## Acceptance and validation

The extracted function can be tested without database/network access and yields the same ordered effects for the same supplied inputs. Execution still uses one authoritative path and the same transaction. Run focused Story effect/decision tests, backend `test:world-runtime`, Contract lifecycle, Player `story-decisions`, `story-delivery`, economic invariants and shared checks.

## Stop / rollback

Stop if pure preparation cannot be separated without changing side-effect/transaction semantics. Do not introduce a queue or second executor to complete the ticket. Revert the extraction and exact caller only.
