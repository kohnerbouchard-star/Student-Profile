Status: VERIFIED_COMPLETE. Risk: R2. Dependencies: REF-031. Maps to ARCH-209/ARCH-401.

## Allowed change

The World-runtime read use case and its read-model dependencies/injection/tests. Proposed scoped read application file under `world/services/` only if the current service is insufficient. No travel cost/eligibility, political/economic policy, campaign progression, route graph, database write or UI changes. Budget: twelve meaningful files.

## Implementation

1. Inventory fields returned by the selected World read and their owners. Separate reference data, game state and private player state; distinguish intentional aggregation from forbidden mutation.
2. Make context, clock and read dependencies explicit while preserving the existing public service signature through a thin adapter if required.
3. Replace selected cross-domain infrastructure imports with approved read contracts. A scoped aggregation repository may remain canonical; do not turn one batched query into many sequential service calls.
4. Keep travel/decision commands outside this read operation and preserve unavailable/partial-data behavior. Do not fabricate World state when a required dependency fails.
5. Characterize two-game isolation, missing campaign/runtime state, paused game, permission denial, optional data absence and response freshness/ordering.

## Acceptance and validation

The read has one documented application owner, no side effects and unchanged public response/query fan-out. Existing travel behavior is untouched. Run backend `test:world-runtime`, `test:player-world`, Player `world-runtime`, `world-news-route`, privacy/capability tests and shared typecheck/architecture gates.

## Stop / rollback

Stop if a proposed interface change requires Story/Campaign redesign or more than the bounded consumer set. Revert the read seam; never repair World data or change campaign progression during a refactor.
