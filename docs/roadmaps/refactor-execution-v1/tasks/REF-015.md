REF-003 candidate register, REF-012–014 parity/removal evidence, current Admin HTML/build/source roots and script/asset audit. Candidate families include the superseded Attendance, Player reset and Settings bridges, but names do not constitute deletion approval.

## Allowed change

At most three confirmed-unused shim files and their exact obsolete loading/export/test references, plus retirement records. No whole `admin/` directory deletion, fetch-stack rewrite, test-suite removal or database/runtime operation. Budget: ten meaningful files.

## Implementation

1. Refresh reachability after the preceding merges. Check modern and retained shells, direct URLs, generated-bundle inputs, delayed/dynamic imports, custom events and browser acceptance paths.
2. For each selected file record replacement commit, old listener/request behavior, zero required callers and why all former behavior is covered. Keep original source recoverable in Git; do not duplicate a large archive unnecessarily.
3. Remove the file and only its now-unused static references. If an old URL must remain for a deployed client, retain a minimal approved compatibility stub and leave deletion BLOCKED until that client is retired.
4. Keep behavioral tests against the canonical owner. Update source-path assertions only where their original behavior requirement remains represented; never delete a negative test because its old filename vanished.
5. Rerun the browser load/interaction crawl and compare request/listener counts. Update actual removed files/lines and remaining candidates, without interpreting the result as a percentage of all dead code.

## Acceptance and validation

No missing asset/script, lost event consumer, duplicate listener or altered action behavior. The exact selected shims have no required caller; all other uncertain candidates remain. Run Admin browser/unit, asset/interaction, legacy-runtime, architecture and secret/diff checks.

## Stop / rollback

Unknown consumer or unexplained console/network failure blocks the individual deletion. Roll back that deletion as a normal source revert; do not resurrect a disabled cloud runtime or weaken the canonical tests.
