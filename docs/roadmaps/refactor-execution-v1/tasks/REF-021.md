Status: VERIFIED_COMPLETE. Risk: R2. Dependencies: REF-016. Maps to ARCH-205/ARCH-401.

`backend/src/domains/economy/api/playerLedgerHistoryHttpHandler.ts`, `staffPlayerLedgerHistoryHttpHandler.ts`, Economy contracts/infrastructure/public index, current ledger query tests and context/privacy rules.

## Allowed change

These ledger-history reads and their minimal repository injection. Proposed `economy/contracts/ledgerHistoryReadRepository.ts` and `economy/infrastructure/supabaseLedgerHistoryReadRepository.ts` only if no equivalent exists. No adjustment, transfer, reward, account-balance or SQL changes. Budget: ten meaningful files; split Staff/Player adapters if parity work exceeds that budget.

## Implementation

1. Record the current query/RPC, game/player/account filters, currency identity, page limits/cursors, sort behavior, row projection and errors for each audience.
2. Extract database details literally into the Economy repository. Keep Staff authorization and Player ownership in their current adapters/application context, not in a browser-supplied filter.
3. Preserve separate audience-specific response projections where privacy differs. Do not expose the raw repository DTO as the browser response or silently change numeric strings to floating-point numbers.
4. Inject the read port from the existing composition root; preserve the approved context and pass only validated filters. No global client or cross-game cache.
5. Compare empty histories, paging edges, identical timestamps, multiple currencies, unknown account/player, wrong game and failed dependency. Assert no mutation command is called.

## Acceptance and validation

Selected handlers contain no raw ledger persistence; result ordering/limits/precision and query count remain unchanged. Checking/Savings, ledger immutability and public identifier privacy remain intact. Run existing ledger-history tests, backend `test:player-banking-public`, `test:economic-ledger-invariants`, `test:player-security`, `test:admin-api`, typecheck/smoke and architecture checks.

## Stop / rollback

Stop if a query change or new index/schema is needed to make the extraction work. Performance improvements are separate. Revert port/injection/source movement only; ledger data is never rewritten.
