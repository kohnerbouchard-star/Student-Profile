## Implementation

1. Recompute counts at the exact source SHA. Separate reachable production source, tests, fixtures, generated output, scripts, historical archives and migration history. Report both file counts and physical-line denominators; do not call either executable-code coverage.
2. Assign one primary disposition per candidate: canonical, confirmed_dead, compatibility_required, legacy_candidate, historical_archive, defensive_fallback, generated_or_fixture or unknown. Track overlapping structural flags separately so percentages are not added twice.
3. Record path/symbol, owner, reason, all inbound roots, dynamic/HTML/build references, SQL/job/HTTP consumers, replacement, evidence query, confidence and removal conditions. `safeToDelete` defaults false.
4. Treat fallback images/defaults, accessibility observers, absent nullable fields and intentional negative-state tests as normal behavior unless source evidence says otherwise. `v1`, `legacy`, file age or zero direct imports is insufficient.
5. Select no more than three low-risk deletion candidates for REF-015/047, each with a proof checklist. External traffic evidence must follow the existing retention policy; do not invent a zero-traffic result.

## Acceptance and validation

The register is reproducible, resolves paths, distinguishes static proof from runtime proof and includes unknowns. Scanner tests include a real defensive fallback, dynamically loaded module, test-only match and externally dispatched handler. Existing architecture ceilings do not increase. Run the shared architecture/legacy checks and JSON/diff checks.

## Stop / rollback

No percentage deletion target is allowed. Retain ambiguous candidates. Revert only the classifier extension if it misclassifies a fixture; application and migration history remain untouched.
