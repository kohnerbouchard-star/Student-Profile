# REF-023 — Expose Inventory reservation contracts to Crafting without new writes

Status: PLANNED. Risk: R3. Dependencies: REF-016. Maps to ARCH-201/ARCH-203/ARCH-402.

## Read first

`backend/src/domains/inventory/` reservation/ownership contracts and existing scoped repositories; `backend/src/domains/crafting/api/playerCraftingHttpHandler.ts`; `crafting/infrastructure/supabasePlayerCraftingRepository.ts`; reservation/crafting lifecycle tests and actual transactional RPCs.

## Allowed change

The Inventory public contract for the selected Crafting dependency and its exact Crafting consumer imports/adapters. Proposed `inventory/index.ts` only if absent; use explicit named/type-only exports, not a repository barrel. No stock-consumption SQL, recipe/equipment rules, job state changes or UI edits. Budget: twelve meaningful files.

## Implementation

1. Identify which existing Inventory symbols Crafting imports deeply, and which reservation/consume/grant actions already occur atomically inside Crafting's database command.
2. Expose the smallest owner-approved reservation/receipt types or command port. Keep database table/RPC implementation details private; bind infrastructure at the existing composition boundary.
3. Redirect only the Crafting consumer family to that boundary. If reservation is internal to one SQL transaction, preserve it and expose only its semantic contract; do not insert an extra JavaScript reservation call.
4. Preserve ownership game/player scope, quantity units, reserve/consume/release order, cancellation/refund semantics and idempotency fingerprints.
5. Test competing Crafting/Marketplace claims on the same stock, insufficient materials, cancellation, failed completion and duplicate requests using existing fixtures/atomicity checks.

## Acceptance and validation

Selected deep imports are removed without creating another inventory authority or increasing transaction count. Reservations cannot oversell or cross games; rollback/replay effects match baseline. Run backend `test:player-inventory`, `test:player-crafting`, `test:player-marketplace`, root `test:crafting-runtime`, owning database/race acceptance and shared checks.

## Stop / rollback

Stop if the proposed abstraction requires splitting an atomic command or exporting raw privileged repositories broadly. Revert only contract/import wiring. Retain any legitimate deep dependency as a documented blocker until an owner-approved boundary exists.
