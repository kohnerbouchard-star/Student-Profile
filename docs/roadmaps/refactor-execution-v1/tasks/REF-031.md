# REF-031 — Separate country reference reads from game-scoped projections

Status: VERIFIED_COMPLETE. Risk: R2. Dependencies: REF-016. Maps to ARCH-101/ARCH-402.

## Read first

`backend/src/domains/countries/infrastructure/supabasePlayerWorldReadRepository.ts`, `api/playerWorldReadHttpHandler.ts`, country read contracts/services and current World data/seed ownership records.

## Allowed change

One Countries read repository's internal reference/scoped projection separation and exact consumer contract/tests. Proposed internal helpers under `countries/infrastructure/` if needed. No schema/seed copy, country identity/name/border, FX policy, travel mutation or map edits. Budget: ten meaningful files.

## Implementation

1. Classify each accessed entity as GLOBAL_REFERENCE, TEMPLATE, GAME_SCOPED, PLAYER_SCOPED or SYSTEM_RUNTIME using schema/source evidence, not its table name alone.
2. Separate stable country reference lookup from mutable game/player projections while preserving current query batching. Require the existing scoped context for every mutable projection.
3. Keep game predicates inside database queries; never fetch all games and filter afterward. Preserve public country keys and safe field projection.
4. Expose a narrow Countries read contract to World consumers if absent, using explicit exports rather than infrastructure deep imports. Do not add a new source of country/economic truth.
5. Compare two games sharing the same reference country but different policy/player state; include missing reference, missing optional runtime data, empty history and failed query cases.

## Acceptance and validation

Reference reuse cannot leak live state between games. Response fields/order/empty behavior and query count match the existing contract. Run backend `test:player-world`, `test:world-runtime`, Player `world-news-route`, `world-runtime`, map-protection and shared privacy/typecheck/architecture checks.

## Stop / rollback

Ambiguous data ownership blocks extraction of that entity; record it for the schema owner without modifying tables. Revert helpers/injection only. No re-seeding or migration is a rollback mechanism.
