# REF-037 — Split Dashboard read composition without increasing query fan-out

Status: PLANNED. Risk: R2. Dependencies: REF-021, REF-026, REF-031. Maps to ARCH-400/ARCH-401.

## Read first

`backend/src/domains/game-dashboard/infrastructure/supabasePlayerGameDashboardRepository.ts`, `api/playerGameDashboardHttpHandler.ts`, large dashboard tests, response contracts and current Player Dashboard capability/read plan.

## Allowed change

One cohesive Dashboard projection family, preferably financial summary, extracted within its read-model owner. Proposed `game-dashboard/infrastructure/dashboardFinancialProjection.ts` if needed. No new aggregation service network hops, ranking rules, financial valuation, dashboard layout or SQL. Budget: ten meaningful files.

## Implementation

1. Record current query batching/concurrency, scoped predicates, error/partial-result policy and order. Dashboard is intentionally cross-domain read-heavy; do not treat every cross-domain read as a violation.
2. Extract one projection's mapping/calculation helpers with explicit inputs while keeping the existing orchestrator and database query plan unchanged.
3. Preserve authoritative balances/positions and currency-scoped presentation; do not derive spendable money from an estimated net worth or merge unlike currencies.
4. Keep capability gating, optional-resource absence, session isolation and public identifier privacy identical. Avoid caches not keyed by game/player/session generation.
5. Compare empty/new-player, multi-currency, missing optional module, large portfolio, dependency failure and cross-game fixtures, recording query count and latency only when actually measured.

## Acceptance and validation

The selected responsibility is independently testable without more queries or sequential fan-out. Current response fields/numbers/ordering and failure states match baseline. Run owning Dashboard tests, backend smoke/typecheck, Player `dashboard-profile`, `dashboard-refresh`, `connected-reads`, banking/market-holdings checks and shared architecture/privacy gates.

## Stop / rollback

Stop if a proposed service boundary makes the read less efficient or changes valuation semantics. Size alone does not require decomposition. Revert the projection extraction and caller together; no data changes.
