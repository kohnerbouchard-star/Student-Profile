# REF-019 — Extract Player clock-in persistence and reuse Attendance authority

Status: PLANNED. Risk: R3. Dependencies: REF-018. Maps to ARCH-208/ARCH-401. Recheck #736 and context ownership.

## Read first

`backend/src/domains/attendance/api/playerAttendanceClockInHttpHandler.ts`, `attendanceRewardPolicy.ts`, REF-018 repository/application boundary, Player request-scope/rate-limit tests and current clock-in SQL/RPC contract.

## Allowed change

Player clock-in handler persistence plus the smallest Attendance-owned application/repository adaptation and tests. Reuse REF-018 contracts only where semantics truly match; do not force Staff and Player operations into a generic unsafe command. Budget: twelve meaningful files. No scanner UI, auth-key, timezone, reward-policy or SQL edits.

## Implementation

1. Freeze the Player-specific auth, rate-limit, game-state and eligibility sequence. Record day/session/timezone boundaries, duplicate-clock-in behavior and idempotency semantics.
2. Extract remaining direct policy/database reads into scoped Attendance infrastructure. Pass the existing frozen Player context through the application; do not read game/player identity from the request body.
3. Delegate economic effects to the same existing atomic Attendance authority. Share a pure policy helper only after equivalent Staff/Player behavior is proven; preserve intentionally different rules.
4. Keep HTTP method validation, safe error mapping and public response fields in the adapter. Do not add blind mutation retries when the service is unavailable.
5. Test midnight/day-boundary and configured timezone fixtures, repeat/concurrent clock-ins, revoked session, wrong game, paused game, failed policy read and rollback.

## Acceptance and validation

One logical clock-in produces the same authoritative reward/attendance/audit effects; identical retry cannot pay twice. The handler's selected raw persistence is gone and no new cross-domain write exists. Run backend `test:player-security`, `test:player-request-scope`, `test:economic-ledger-invariants`, Attendance suites/disposable race cases, full smoke/typecheck and shared guards.

## Stop / rollback

Stop on an unresolved login/throttle incident or required policy/schema change. Revert only this application/repository adapter; preserve accepted service-role fixes and all ledger history.
