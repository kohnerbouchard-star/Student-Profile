# REF-020 — Isolate Staff-login persistence without changing authentication

Status: PLANNED. Risk: R3. Dependencies: REF-005. Maps to ARCH-100/ARCH-401. Activation requires reconciled #668/#736 ownership and a known-good auth baseline.

## Read first

`backend/src/domains/auth/api/staffLoginHttpHandler.ts`, adjacent Staff login tests, Auth contracts/infrastructure, current Staff/Admin composition roots and web-session security tests. Read recently merged key/nonce authority fixes; do not revert them while moving code.

## Allowed change

Only Staff-login database persistence behind a narrow existing/new Auth repository port. Proposed `auth/contracts/staffLoginRepository.ts` and `auth/infrastructure/supabaseStaffLoginRepository.ts` if needed. Provider authentication, BFF cookie/nonce/CSRF behavior, MFA, signup/recovery and shared key selectors stay unchanged. Budget: ten meaningful files.

## Implementation

1. Separate provider credential validation from application-profile/membership persistence. Record their exact ordering and which failures are externally distinguishable.
2. Extract only the raw profile/membership query/update calls into Auth infrastructure; retain approved server-side `auth.getUser`/provider checks and do not trust claims without current validation.
3. Inject the repository from the current root. Do not construct a new global service client, broaden a key selector or pass service-role credentials as a user bearer.
4. Preserve rate-limit and anti-enumeration responses, safe error categories, no-store headers, active/disabled Staff handling and multi-game/bootstrap ownership.
5. Test valid Staff, invalid credentials, disabled account, missing profile, revoked session, repository failure and unavailable throttle service. Inspect logs/fixtures for secret or credential leakage.

## Acceptance and validation

Selected persistence leaves the HTTP handler without changing auth authority, timing/order categories, public envelope or session result. Run root `test:auth-boundaries`, `test:web-session-release`, backend `test:admin-api`, relevant Staff tests, full typecheck/smoke and architecture/security guards. Staging authenticated login/bootstrap must be checked before any separately authorized release.

## Stop / rollback

Stop if the change touches an active auth repair or requires altered login/session semantics. Revert only this persistence extraction, never to an earlier vulnerable authentication implementation or revoked secret.
