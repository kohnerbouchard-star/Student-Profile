# REF-044 — Split Admin V2 Contracts rendering from controller state

Status: PLANNED. Risk: R2. Dependencies: REF-007, REF-008, REF-009, REF-043. Maps to ARCH-500/ARCH-501.

## Read first

`admin/v2/src/routes/contracts/ContractsController.js`, `ContractsRoute.js`, current Contracts API client and shared table/dialog/focus primitives. Read the actual submission-detail rendering function and its callbacks before selecting the seam.

## Allowed change

Only submission-detail presentation extracted from its current owner, with explicit state/action callbacks and focused tests. Proposed `routes/contracts/ContractSubmissionDetail.js` if absent. No whole-screen rewrite, CSS redesign, route/capability expansion or review/reward semantics change. Budget: eight meaningful files.

## Implementation

1. Record rendered fields, action enablement, identifiers, data-state branches, event callbacks, focus ownership and current DOM/class contracts.
2. Extract a presentation function receiving already-authorized safe view data and callbacks. It must not fetch, mutate, evaluate Staff permissions independently or own a second selected-game state.
3. Leave load/review/reward orchestration, request cancellation and authoritative refetch in the existing controller. Reuse shared dialog/table primitives without changing their global API.
4. Preserve form values, validation messages, empty/loading/error states, keyboard behavior and focus restoration across review completion or remount.
5. Exercise long titles, many submissions, denied capabilities, failed review, replay, selected-game switch and stale responses at current desktop/mobile breakpoints.

## Acceptance and validation

Same screen/actions/DOM behavior, with presentation separate from controller state and no new network request or event leak. Run Admin V2/Contracts unit/browser tests, root `test:admin-local-mutation-ui`, `audit:interaction-wiring`, affected backend review/reward tests and shared guards. Screenshots/geometry checks verify preservation, not a new approved design.

## Stop / rollback

Stop if the extraction becomes a redesign or requires backend changes. Revert the view component and callback wiring together; do not weaken accessibility or action-permission assertions to pass.
