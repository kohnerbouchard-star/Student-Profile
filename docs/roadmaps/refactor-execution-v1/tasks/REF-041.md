Status: VERIFIED_COMPLETE (bounded repository qualification of the existing shared lifecycle). Risk: R2. Dependencies: REF-005. Maps to ARCH-500/ARCH-502. Recheck #624 before touching Player data/realtime ownership; no CSS changes.

`player-terminal/src/api/read-model.js`, `resource-status.js`, the current Inventory read resource registration/adapter, `features/inventory/inventory-read-model.js`, session-generation and read-ordering tests. Reuse the existing data plane rather than introducing a new cache library.

## Allowed change

The Inventory resource's duplicated read-status/loader adaptation and exact shared helper it already consumes. No other resource migration, endpoint, transport authentication, capability schema, polling interval or page/CSS redesign. Budget: ten meaningful files.

## Implementation

1. Trace resource ownership, loading/empty/error/success states, cancellation, deduplication, cache/session key and stale-result rejection.
2. Extract/reuse one explicit resource lifecycle helper only where current Inventory code duplicates it. Preserve the existing loader's request/result shape and resource-status semantics.
3. Keep session-generation tokens and abort signals attached through completion; old-session responses must not populate the new player's state.
4. Preserve fail-closed capabilities and staging/production preview-data exclusion. An unavailable backend is not permission to substitute demo inventory or a zero balance.
5. Compare concurrent reads, out-of-order completion, abort, logout/game switch, failed read/recovery and empty results using current fake transports; record request counts.

## Acceptance and validation

Inventory uses one lifecycle owner with the same request count, error states and stale-response protection. Other resources remain untouched. Run Player `read-ordering`, `connected-reads`, `session-browser-safe`, `inventory-read`, `recovery`, `runtime-integration`, `verify` and shared architecture/interaction checks.

## Stop / rollback

Stop if #624 or another owner modifies the same runtime paths, or a new global state/caching architecture is needed. Revert only the selected lifecycle/helper wiring; never weaken capabilities or preview isolation to recover a failed test.
