# REF-030 — Separate Contract submission translation from Story decision behavior

Status: VERIFIED_COMPLETE (bounded repository seam). Risk: R3. Dependencies: REF-029. Maps to ARCH-208/ARCH-400.

## Read first

`contracts/api/playerContractPublicSubmitHttpHandler.ts`, `playerContractStoryDecisionSubmitHttpHandler.test.ts`, existing Story decision application/services and public Contract submission contracts. Use the actual dispatch path; do not infer equivalence from similar action names.

## Allowed change

One submission request translator and its explicit dispatch to the existing Contract or Story owner plus tests. Proposed internal translator: `contracts/api/playerContractSubmissionAdapter.ts` if needed. No new choice options, free-text policy, reward approval, Story state machine, SQL or browser form changes. Budget: twelve meaningful files.

## Implementation

1. Freeze how the current handler identifies normal submissions versus Story decisions, including public identifiers, action payload validation, required context and status/error envelopes.
2. Extract transport parsing/normalization into a bounded adapter. It must return the existing owner-specific command rather than execute side effects during parsing.
3. Dispatch to the current Contract submission or Story decision authority exactly once. Preserve transaction/replay identity and any coupling that must remain atomic; do not write both owners independently.
4. Keep eligibility/deadline/relationship effects, audit records and response privacy in their established authoritative paths. Do not redesign a narrative decision because its current interface is inconvenient.
5. Test both submission modes, malformed/ambiguous payloads, wrong game, expired eligibility, duplicate/conflicting replay, denied decision and downstream failure.

## Acceptance and validation

Same inputs select the same owner and produce the same public result/effect counts. Parsing has no database write; neither path can fall through and execute the other. Run backend Contract acceptance/lifecycle, affected Story tests, Player `contracts-submit`, `story-decisions`, `story-delivery`, economic invariants and shared guards.

## Stop / rollback

Stop if separation changes domain authority or transaction boundaries. Record ambiguous product behavior for a separate decision. Revert only parsing/dispatch extraction; preserve all story/contract data and historical migrations.
