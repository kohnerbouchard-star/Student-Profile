# REF-025 — Bound Business-banking and loan reads behind explicit contracts

Status: BLOCKED. Risk: R2. Dependencies: REF-021. Maps to ARCH-205/ARCH-207.

## Read first

`backend/src/domains/business-banking/api/playerBusinessBankingHttpHandler.ts`, its existing contracts/infrastructure; Economy and Banking-FX public indexes; Business treasury/read contracts; actual loan read owners found by the route census. Do not assume personal Loans belongs to Business banking merely because the older domain name is broad.

## Allowed change

One currently reachable business-banking read projection and its context/public-import boundary. Resolve the exact repository at activation. No personal/business account merge, lending algorithm, interest, repayment, FX fixing, balance authority or UI edits. Budget: ten meaningful files.

## Implementation

1. Map each field in the selected read to its authoritative source: business ownership/mandate, account balance, currency, loan status or terms. Record unrelated personal Loans routes separately.
2. Reuse existing Economy/Business/Banking-FX contracts and expose only the narrow needed read port where missing. Preserve efficient scoped read-model aggregation instead of adding an N+1 service call per account.
3. Move only database-specific projection/persistence currently outside the appropriate repository. Pass the approved Player context and verify business operating/treasury authority separately from share ownership.
4. Preserve exact numeric representation, currency grouping, Checking/Savings distinctions, loan state and unavailable-resource behavior. Do not present absent values as zero or combine currencies without the existing valuation contract.
5. Test no business, multiple businesses, shareholder without operating mandate, wrong game, unavailable lending resource and mixed currencies.

## Acceptance and validation

Selected read dependency has one explicit owner and unchanged query/result semantics. Banking-FX's clean implementation is preserved rather than rewritten. Run backend Banking/FX/economic suites, relevant Business-banking/loan tests from their current manifest, Player `banking-read`, `banking-fx`, `business-workspace` and shared guards.

## Stop / rollback

If loan ownership is ambiguous, record it; do not relocate the whole lending system. Revert only the selected read port/import/injection. Money/loan state must never be migrated during this task.
