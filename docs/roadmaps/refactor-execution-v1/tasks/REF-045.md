# REF-045 — Isolate licensing issuance from worker transport

Status: PLANNED. Risk: R3. Dependencies: REF-005. Maps to ARCH-302/ARCH-600.

## Read first

`backend/supabase/functions/license-issuance-worker/index.ts`, Licensing application/contracts/infrastructure, current entitlement/issuance lifecycle tests, payment webhook callers and `license-email-worker` as a protected adjacent consumer.

## Allowed change

One issuance-worker application invocation and its exact domain-owned extraction/tests. No real Stripe/payment request, webhook deletion, subscription/price change, email send, entitlement rule, queue/lease schema or deployment config. Budget: ten meaningful files.

## Implementation

1. Trace worker authentication, due-job claim/lease, payment provenance, entitlement issuance, idempotency, retry and email handoff. Determine which steps are already application-owned.
2. Move only misplaced issuance business logic behind the existing Licensing use case; leave transport/auth/due-work adaptation in the worker. If already thin, record verification-only disposition.
3. Preserve current payment-signature/provenance checks and one authoritative issuance transaction. Do not merge similarly named payment webhooks without proving their consumers and contracts.
4. Keep retries, claim ownership, entitlement limits and duplicate-event outcomes unchanged. External calls remain injected/mocked in tests; no production billing/email credentials in local execution.
5. Test duplicate payment/job delivery, expired claim, invalid provenance, already-issued entitlement, failed persistence and email handoff failure with existing synthetic fixtures.

## Acceptance and validation

One existing issuance authority remains, with identical entitlement/job/audit effects and no duplicate license/email side effect. Run current Licensing worker/lifecycle tests from their owning registration, backend typecheck/smoke, internal-runner/auth checks and shared architecture/security gates. Payment/runtime certification remains separate.

## Stop / rollback

Stop if real payment/provider changes or SQL transactions are required. Revert source extraction only. Never revoke/issue real licenses, replay payments or send real emails to test or roll back the refactor.
