# REF-027 — Contain the retained Business-creation compatibility seam

Status: PLANNED. Risk: R3. Dependencies: REF-025, REF-026. Maps to ARCH-207/ARCH-700. Preserve the completed Business V2 authorities.

## Read first

`backend/src/domains/business/index.ts`, current Business API/application/infrastructure, callers of `create_or_acquire_player_business_v1`, and the immutable legacy-creation/ownership-continuity/legacy-sales-retirement migrations. Read the current Business checkpoint and Phase 14 scope documents.

## Allowed change

A source-level compatibility caller/adapter inventory, one minimal TypeScript containment seam if a live caller needs it, and targeted tests. No SQL function/trigger deletion, migration rewrite, ownership/equity/workforce/accounting/IPO redesign or force-migration of existing businesses. Budget: ten meaningful files.

## Implementation

1. Enumerate runtime, SQL/trigger and test consumers of the legacy creation function. Distinguish historical definitions from current callable authority; repository search cannot prove live RPC non-use.
2. Record which legacy actions remain intentionally supported and which acquisition/sales branches are already retired. Keep current server-owned tax classification, ownership continuity and initial-funding semantics.
3. If a TypeScript caller remains, isolate its request/response translation in one explicitly named compatibility adapter delegating to the existing authority. Do not copy Business formation logic or add a second cap-table writer.
4. Block growth of new callers with a narrow existing ratchet/test. Expose current Business V2 contracts to new consumers instead.
5. Preserve all healthy Business modules. When no source change is warranted, finish as an evidence/containment-only ticket and list database retirement as a separate approval-dependent work item.

## Acceptance and validation

One documented canonical creation authority and explicitly bounded compatibility remain; no new legacy caller or economic writer. Current formation/funding/ownership continuity and forbidden-acquisition tests pass, along with Business workspace/boundary and the exact Business workflow matrix resolved from the checkpoint. No deletion percentage is imposed.

## Stop / rollback

Live legacy usage unknown means retain. Removing SQL routines/triggers needs separate forward migration and release authorization. Revert only the source adapter/ratchet change, never corporate ownership records, financial statements or applied migrations.
