## Scope and implementation

Only POST `/games/:game/contracts/:contract/progress/:progress/rewards/issue` was cut over from the shared proxy dispatch to `admin-api/contractRewardIssueOperation.ts`. The prior `proxyClassroom` path already intercepted this route locally; this removes routing indirection, not an outbound Classroom settlement request.

The adapter requires the approved server-derived game-admin/staff/game/`contracts.manage` context before effects. Contract and progress identity come from the route; game and staff identity come from approved context, not the request body. It calls unchanged `issueContractRewardsAtomically` exactly once. The helper invokes unchanged `issue_contract_rewards_atomic_v1` with `p_game_session_id`, `p_contract_id`, `p_progress_id`, `p_staff_user_id`, and `p_request_id`. Eligibility checks, row locks, monetary and item settlement, story flags, progress, issuance receipt, and audit remain within the existing atomic database authority.

Request identity remains `x-request-id`, then `idempotency-key`, then `x-idempotency-key`, then the existing UUID audit fallback only when no nonempty transport identity was supplied. Supplied identities are not regenerated. Success and failure use the shared JSON response helper, preserving status, error envelope, `application/json; charset=utf-8`, CORS, `Cache-Control: no-store`, and reward receipt values.

Scoped coupling before/after: shared proxy dispatch for this route 1→0; calls to the authoritative reward helper 1→1; outbound Classroom fetches 0→0. Shared proxy compatibility remains for other routes and is not claimed retired. No Banking/Inventory/Progression split was introduced.
