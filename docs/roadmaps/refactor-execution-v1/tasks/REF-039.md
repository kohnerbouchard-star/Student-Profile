# REF-039 — Separate Stock-runner triggering from tick execution

Status: PLANNED. Risk: R3. Dependencies: REF-038. Maps to ARCH-206/ARCH-600.

## Read first

`backend/supabase/functions/stock-market-orchestrator/index.ts`, `stock-market-runner/index.ts`, `backend/src/domains/stocks/api/stockMarketRunnerHttpHandler.ts`, existing runner/services/repositories and scheduler/lease/calendar tests.

## Allowed change

One runner/orchestrator responsibility identified as duplicated or misplaced: due-work discovery versus existing tick-use-case invocation. Proposed internal Stocks application adapter only if missing. No schedule, lease schema, market calendar, batch limit, retention, deployment configuration or engine formula edits. Budget: twelve meaningful files.

## Implementation

1. Trace scheduling authority, due-game selection, lease acquisition, internal-runner auth, tick identity, retry and commit. Identify logic already domain-owned before extracting anything.
2. Leave cron/HTTP adaptation in the entrypoint and delegate the selected existing execution step to the Stocks application owner with explicit game/time/lease context.
3. Preserve one tick identity, lock/lease semantics, batch bounds and retry rules. Do not execute a tick both in the orchestrator and runner or invent a second schedule.
4. Keep paused-game/closed-exchange handling and deterministic engine inputs unchanged; do not move nondeterministic time reads into a different stage.
5. Test duplicate trigger, competing runner, expired lease, partial dependency failure, market closure and cross-game work discovery using existing synthetic/disposable fixtures.

## Acceptance and validation

Entrypoint only triggers the same owner; one logical due tick commits at most once with unchanged results and bounds. Run backend `test:stock-market-calendar`, owning runner tests, root `test:market-trigger`, auth/lease/economic checks, full typecheck/smoke and architecture audits. Live cron behavior is not certified by these tests alone.

## Stop / rollback

Stop if schedule/lease/transaction changes are required or another release owner touches the entrypoint. Revert source wiring only; do not replay or delete live ticks, adjust cron or release a production lease manually.
