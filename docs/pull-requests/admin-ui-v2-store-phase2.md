## Summary

Migrates Store Management as the second native route in the source-owned Admin v2 shell and introduces a canonical repository-owned Store item media resolver shared with the Player Store. Overview remains native and unchanged. World Management remains a first-class left-navigation item. Every route other than Overview and Store keeps its Phase 1 legacy or planned disposition.

The Store page reads, creates, edits, and archives items through the existing same-origin HttpOnly Admin BFF. It adds no Backend endpoint, database or Supabase change, authentication or authorization policy, rate-limit change, Player purchase behavior, or legacy Admin behavior.

## Existing API and security boundary

The browser continues through `/api/admin` with `credentials: "include"`, the existing device identity, selected-game binding, publishable key, no-store behavior, and redirect rejection. The v2 transport is local and dependency-injected; it does not patch global `fetch`, a prototype, or a DOM API.

For a mutation, the transport rejects an unauthenticated, expired, or malformed session before the request is issued, derives CSRF from the validated session boundary, and canonicalizes one `Idempotency-Key`. Server-side authentication, AAL2, `store.manage`, game ownership, user-action rate limiting, audit identity, and transactional idempotency remain authoritative and unchanged. Errors are projected to the existing safe Admin envelope; raw Backend, SQL, Supabase, stack, function, service-role, environment, and private-ID details never enter the DOM.

## Persisted fields and deliberate omissions

The dialogs expose only fields supported by the current Store DTO and mutation routes: `name`, `description`, `category`, `price`, `currencyCode`, `stockQuantity`, `status`, `visibility`, and `sortOrder`. The persisted create-only `itemKey` remains generated by the authoritative create contract and is not presented as an Admin control.

The current DTO does not persist custom media, and the existing mutation boundary rejects Store image multipart uploads until a storage/media policy exists. This PR therefore contains no upload UI and ignores arbitrary item-supplied image URLs. It also does not add controls for unlimited stock, country stock, restock, fulfillment, or usage configuration. Read-only purchase statistics may be displayed when the existing GET projection returns them.

Archive is the product label for the established `DELETE` contract, which performs a soft archive. This PR does not claim a hard delete or invent a restore operation.

## Canonical media contract

`player-terminal/assets/store-item-media.mjs` maps public Store item keys to allow-listed repository assets:

- seeded keys use the existing country WebP artwork under `player-terminal/assets/images/items/store/**`;
- allow-listed catalog keys use existing SVG artwork under `player-terminal/assets/store-items/**`;
- custom, malformed, unsupported, missing, and private-key cases use `player-terminal/assets/store-item-placeholder.svg`.

The descriptor carries source, accessible alternative text, media kind, and the deterministic fallback source. Admin and Player Store error paths converge on the same graphical placeholder. No glyph, initial, raw URL, external image, or fake upload state substitutes for missing artwork.

The Player change is intentionally narrow: its Store artwork adapter delegates to the canonical resolver with a Player-relative asset base, Store cards opt into deterministic load-error fallback, and the existing legacy Marketplace local-SVG compatibility is kept separate. Player purchasing, item availability, balances, inventory, and route behavior do not change.
