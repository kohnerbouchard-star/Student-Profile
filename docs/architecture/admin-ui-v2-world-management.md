Owner branch: `refactor/admin-ui-v2-world-management-v1`

## Scope

World Management remains a first-class Admin route. This migration replaces the planned V2 boundary with a source-owned supervisory surface for the authoritative, game-scoped World runtime.

The implementation is intentionally bounded to existing World administrator contracts. It does not create a second World model, does not add Backend/database endpoints, and does not absorb News & Events.

## Authoritative contracts

The current Admin World handler exposes these reads:

- `GET /api/admin/games/:gameId/world/campaign`
- `GET /api/admin/games/:gameId/world/campaign/history?limit=100`
- `GET /api/admin/games/:gameId/world/campaign/effects?status=all&limit=100`
- `GET /api/admin/games/:gameId/world/arrival-classes?limit=100`
- `GET /api/admin/games/:gameId/world/geography`
- `GET /api/admin/games/:gameId/world/travel?limit=100`
- `GET /api/admin/games/:gameId/world/residency?limit=100`

The V2 surface exposes only mutations already supported and already represented by the existing Admin workflow:

- campaign pause;
- campaign resume;
- campaign emergency disable;
- failed effect recovery;
- Arrival Class correction to one of the eight existing class IDs;
- route close;
- route reopen.

Campaign manual trigger is deliberately not surfaced. Its authoritative Backend contract can emit News/notifications/market/store effects and therefore crosses the explicit News & Events boundary for this migration.

The Backend also supports `correct_phase`, `restricted` routes, arbitrary route multipliers, and other lower-level inputs. They are not exposed because the current Admin workflow does not present those as reviewed operator controls.

## Countries, currencies, and economic configuration

There is no current World Admin mutation contract for country definitions, currency definitions, or FX rates. V2 therefore does not invent one.

Country supervision is derived from authoritative World state already returned by geography, Arrival Class, and residency reads. Currency supervision is derived from authoritative residency and travel currency codes.

World economic configuration shown here is limited to data present in the current World contract: runtime pack/version/revision, route costs/durations/multipliers, residency currencies, and travel settlement currencies/costs.

## Data ownership and private IDs

`WorldManagementController` normalizes the Backend DTO into a presentation model and explicitly drops private ownership identifiers, including `player_id`, UUID-shaped text, definition digests, idempotency keys, effect payloads, and other implementation-only fields.

Public World identifiers such as `cmp_*`, `cec_*`, `acl_*`, and `rte_*` are retained only where required to invoke authoritative mutations. They are not rendered as user-facing identifiers.

Unicode is preserved. Korean and long location/country labels are not ASCII-normalized or converted into private tokens.

## Authentication and game scope

The route-owned `WorldManagementApi` uses the existing `createAdminBffTransport` by default. The browser therefore remains behind the same HttpOnly Admin BFF boundary as other native V2 routes.

That boundary:

- applies the selected game scope;
- requires the current administrator session for mutations;
- injects CSRF and device identity;
- requires canonical idempotency keys;
- strips browser-provided Authorization and Cookie headers;
- preserves server-side permission, AAL2, rate-limit, and audit enforcement.

The V2 route registry also requires `world.manage` before the controller is loaded.

## State model

World Management uses the shared Admin V2 six-state lifecycle:

- initial loading;
- ready;
- refreshing;
- stale;
- empty;
- failed.

The seven authoritative read panels settle independently. Partial failures keep valid panels visible with a safe availability notice. If every panel fails, the route enters failed/stale state through the shared V2 state machine.

A refresh failure after a successful read keeps the last good model as `stale`. All World mutations are disabled unless the controller is in a fresh `ready` state, preventing high-impact changes from stale revisions.

An empty authoritative projection with no runtime, campaign, geography, effects, Arrival Class, travel, or residency data is presented as an uninitialized World rather than fabricated defaults.

## Mutation safety

Every exposed mutation is reviewed through an `AdminConfirmDialog`.

Campaign, Arrival Class, and route mutations use authoritative revision values. Effect recovery and all other writes use idempotency keys generated by the controller. A successful write is reported independently from the follow-up refresh so a read failure cannot be mistaken for a failed committed mutation.

Route close/reopen intentionally preserves the existing Admin semantics:

- close: `status=closed`, `reason=war`, neutral 10,000 basis-point cost/duration multipliers;
- reopen: `status=open`, `reason=recovery`, neutral 10,000 basis-point cost/duration multipliers.

## Responsive presentation

Desktop uses V2 summary cards, section cards, facts, and data tables. At 900 px and below World tables become stacked record cards instead of compressed grids. At 640 px and below summary/fact layouts become single-column and controls expand for touch use.

## Shared edits

Shared changes are deliberately limited to:

- `admin/v2/src/core/navigation-registry.js`: World Management `planned -> v2`;
- `admin/v2/src/app.js`: controller composition and lifecycle;
- `admin/v2.html`: World route stylesheet.

All World code otherwise lives under `admin/v2/src/routes/world-management/` and `admin/v2/styles/routes/world-management.css`.

`news-events` remains `planned` and no News & Events implementation is included.
