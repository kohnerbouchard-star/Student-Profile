2026-10-05; reviewed source main `091539a2b735f9516808294efa60b553b7cf1a18` (C0). Status: PROPOSED, awaiting parent review before the first disablement. Documentation only; no path disabled, no elapsed observation credited, no task completion. REF015 remains BLOCKED; REF047/048 still depend on it.

The user reports that no actual games are operating and explicitly requested remaining caller migration, representative Admin/Player tests and one-at-a-time reversible disablement instead of relying on an idle quiet period. This is a user-provided operating constraint, not independently verified telemetry. Reconfirm it before each experiment and before the next real game. Inactivity does not establish absent Admin, bookmarked, cached or standalone consumers.

This proposal is a narrow REF015 exception for controlled, non-production browser caller cutovers. It does not amend cloud runtime/credential retirement, release authority, authentication, ledger/isolation controls, logging retention or production deployment rules. The general [retirement policy](../../../legacy-runtime-retirement-v1.md) remains unchanged. No permanent deletion is proposed. A hosted disablement, old-URL removal or permanent deletion needs its own explicit reviewed authorization and applicable evidence; the existing 14/7/30 policy is not silently waived for those operations.

## Proposed replacement conditions — not yet executed or accepted

The 24-hour observation and seven-day recovery-package minimum below are new explicit amendment terms proposed for parent review. They are not elapsed evidence, automatic authorization, or a waiver of unresolved consumers. Until accepted for an exact per-path scope, they replace no existing gate. Even after acceptance, retaining a needed old URL/fallback earns only a bounded caller-migration milestone, not full REF015 closure: task status remains BLOCKED and REF047/048 dependencies remain until the task's removal acceptance is independently justified. Neither this document's merge nor all eight caller migrations automatically establishes that acceptance. Acceptance of this amendment authorizes only the bounded caller-disable milestones explicitly reviewed per path. Full amended Task15 completion criteria require a separate review and decision; required retained URLs or unresolved consumers do not close Task15 or unlock REF047/048.

1. **Before one caller is disabled:** replace the 14-day idle-traffic prerequisite for this limited experiment with affirmative baseline/candidate/rollback evidence on exact commits. Run each row's journey in a fresh browser profile, a warm cached profile, the retained raw Admin shell, built default Admin V2 and a synthetic Player session. Exercise a bookmarked route and direct/query-suffixed legacy URL where applicable. Include denial, timeout/offline, retry, context change and duplicate-action cases. Record requests, listener/observer counts/order, global/events, console errors, assets and expected UI. Two independently launched candidate sessions must pass; the rollback rehearsal must pass before proceeding. A green historic suite is not substitute evidence.
2. **Parent decision:** inspect the exact row's caller map, diff, source/build identities, test artifacts and rollback rehearsal. Record the accepted single path and exact candidate commit. Unknown clients must either keep a tested compatibility route or block removal of that route; “no games” is not a waiver. No other path is disabled concurrently.
3. **Shortened observation:** propose 24 hours after the controlled caller cutover, with affirmative synthetic journeys at T0, at least four hours later, and at/after T+24h including a cold restart. The next path may start only after all three sessions and parent review pass. Empty traffic does not count as a session; missed sessions extend the window. Record actual UTC times, never backfill elapsed time. This replaces the seven-day observation only for the reviewed non-production caller experiment. If a real game/user appears, pause this exception and reassess before continuing.
4. **Recoverability:** propose keeping the exact tested rollback package immediately available for at least seven days after acceptance AND through the first representative rehearsal of the next game, whichever is later. Retain compatibility URLs and Git source history beyond that period; seven days is not permission to delete anything. The general 30-day pre-permanent-deletion condition remains outside this proposal and unchanged. No existing artifact/log retention setting is altered; if an expiring CI artifact cannot satisfy this duration, save a hash-verified local recovery package before acceptance.
5. **Stop/revert:** any lost/duplicate write, incorrect error/success state, changed credential/session behavior, missing asset/global/event, duplicate listener, changed capture order, stale-game UI/write, unexplained request, inaccessible modal/focus regression, unknown caller needing a disabled entry, incomplete evidence or untested rollback blocks the row. Restore only its caller change, rerun its failing journey and common checks, and restart its representative-use sessions. No timeout increase, swallowed exception, removed negative test or unrelated control change to obtain a pass.
